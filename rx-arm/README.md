# rx-arm — АРМ руководителя как сторонний контрол Directum RX

Экран MVP 1-го этапа («обзор поручений» для руководителя ПТО) в виде штатного стороннего
контрола RX-веб: Remote Component, Webpack Module Federation, scope `Cover`.

**Источник вёрстки — макет `2026-09-04-mvp-screen-rx_v2_fixed` (`fixed (2).mhtml`).** Дизайн,
лэйаут, цвета, отступы и глифы перенесены дословно; правило работы: _макет главнее текста_.
Если в коде что-то расходится с макетом и это не описано ниже в «Отличиях» — это дефект,
а не улучшение.

**Один контрол на весь экран, а не по контролу на блок.** Так порядок блоков и их ширина
(все четыре — во всю ширину, 12 колонок) фиксируются самим компонентом и не зависят от того,
как редактор обложки разложит контролы по колонкам.

`data.ts` (демо-датасет и вычислительная логика), `<Name>.tsx` (компонент).

- `src/dashboard/Dashboard.tsx` — экран целиком: сетка `.cfgw-grid`, четыре блока, диалог.

- `src/shared/arm.css` — **вся вёрстка**: style-блок макета один в один, каждый селектор
  отскоплен классом `.rx-arm-root`, чтобы стили не протекали в DOM хоста. Генерируется
  скриптом из макета, руками не править — править макет и перегенерировать.

- `src/shared/icons.tsx`, `src/shared/tokens.ts` — глифы Tabler и цвета для инлайн-стилей.

- `src/standalone/Preview.tsx` + `index.js` — превью без хоста с переключателем ширины.

## Отличия от макета — осознанные, других нет

Пункты 1, 4 и 5 — адаптация к хосту; все три собраны в блоке хост-адаптации
`tools/scope_css.py`, и он падает с понятной ошибкой, если соответствующее правило
в макете изменилось.

1. **Медиа-запрос → контейнерный запрос.** В макете раскладка ломается по ширине окна
   (`@media (max-width:1100px)`), контрол же знает не окно, а ширину своей области —
   поэтому `@container`, контейнер объявлен на `.wrap` (канон `rx-cover`).
   Контейнер именно на `.wrap`, а не на корне: `container-type` включает containment, и корень
   стал бы containing block для `position:fixed` — оверлей диалога перестал бы раскрываться
   на весь экран. Поэтому диалог рендерится соседом `.wrap`, а выбор сотрудников живёт
   в состоянии экрана, а не внутри блока сотрудников.
2. **Вкладки блока 3 работают, и их счётчики считаются по данным.** В макете вкладки —
   картинка со счётчиками «Все 12 / Просрочено 3 / Срок сегодня 1», а строк всего пять.
   Чтобы метрики сходились друг с другом (нерушимое правило проекта, см. корневой `CLAUDE.md`),
   в демо-датасете лежат все 12 поручений; вид по умолчанию совпадает с макетом строка в строку.
3. **Поведение диалога доведено до рабочего**: черновик выбора, «Применить» перерисовывает
   блок, «Отменить»/Esc/×/клик по фону откатывают, поиск фильтрует, пустой результат —
   «Ничего не найдено». Лимита в шесть сотрудников нет (решение по макету от 04.09), поэтому
   нет и заблокированных строк `.armp-dis`, и подписи `.armp-note` — класс в CSS оставлен
   на случай возврата лимита.
4. **Подложку рисует хост, не контрол.** Макет — отдельная страница и красит фон сам
   (`--page`, серый); на обложке это выглядело серой заплаткой на белом фоне RX. Корень
   контрола прозрачный, цвет подложки берётся у хоста. Правка в блоке хост-адаптации
   `tools/scope_css.py`.
5. **Ограничение ширины снято.** В макете `.wrap{max-width:1440px}`; на обложке при
   отдалении (Ctrl+колесо) виджеты переставали растягиваться и по краям оставались пустые
   поля. Ширину задаёт хост. Там же, в `tools/scope_css.py`.
6. **В карточке сотрудника нет ссылки «Поручения в RX».** В список поручений будем
   проваливаться по клику на саму карточку — обработчик появится вместе с переходом.

## Иконки

Глифы шапок виджетов — цветные SVG из UI kit Directum RX (набор «Обложка»),
вшиты в бандл как data-URI. Системные `settings, search, x, check, arrow-narrow-right` —
сабсет Tabler Icons 3.11.0 (MIT) в `arm.css` как `@font-face` (`rx-arm-tabler-icons`).
Новый глиф Tabler = пересобрать сабсет и дописать `.rx-arm-ti-<name>:before`. Новый глиф RX =
экспорт из Figma «Обложка» → `tools/extract_picked_icons.py` → `src/shared/rx-icons/`.

Классы UI с префиксом `rx-arm-` (или уже уникальные `arme-`/`armk-`/`dcp-`), корень
`.rx-arm-root` — изоляция от CSS хоста без CSS Modules.

## Сборка и запуск

```bash
npm install
npm run start:dev:standalone   # webpack watch + serve :3003
npm run build:dev:standalone   # автономная сборка в dist/
npm run build:release          # прод-бандл (remoteEntry.js + metadata.json)
npm run type-check             # tsc --noEmit
npm run lint                   # ESLint (в т.ч. no-unsanitized, no-explicit-any)
npm run prettier:check         # Prettier
npm run check                  # type-check + lint + build:dev:remote
```

Нужен доступ к пакетам `@directum/sungero-remote-component-*`.

## Деплой

1. `npm run build:release` → `dist/` (`remoteEntry.js`, `metadata.json`, chunks, css).
2. Разместить `dist/` на URL, доступном веб-клиенту RX.
3. Зарегистрировать в RX: **Настройки → Компоненты → Добавить** → URL `…/metadata.json`.
4. На обложке модуля: **Добавить → Специальный контрол** →
   `ARMGov_LeaderCover_1_0.LeaderDashboard` (scope Cover).

## Открытые пункты (проверять на стенде)

- **Данные.** Сейчас всё из демо-пресетов `data.ts`. Контракты (`types.ts`) написаны под
  подключение к источнику; сам источник (API дашборда или прикладной слой RX) не выбран.
  Хост-API Cover: `onControlUpdate` уже синхронизирует тему/культуру (`ArmRoot` /
  `data-theme`); `executeAction` / данные — позже.
- **Рамка карточки.** Как и в `rx-cover`, карточку рисует сам виджет. Проверить, не рисует ли
  группа хоста поверх свою рамку/тень — будет дубль.
- **Внешние отступы.** Корень контрола прозрачный (подложку даёт хост), но
  `.rx-arm-wrap{padding:20px}` остался — поверх полей области обложки отступы могут
  быть шире макетных. Если на стенде заметно — обнулить padding.
- **Тема хоста.** `onControlUpdate` пишет `data-theme` на `ArmRoot`; для Night есть
  локальные токены. Полный маппинг на `--theme_*` хоста — по мере подключения данных.
- **Фото сотрудников** — стоковые, вшиты в бандл (~80 КБ base64). На стенде заменяются
  ссылками на фото из карточек сотрудников RX.
