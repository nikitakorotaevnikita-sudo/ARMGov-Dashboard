# Управляемый workflow аналитики на Qwen и Microsoft Agent Framework

Дата: 2026-09-20. Статус: решение согласовано на уровне направления; реализация не начата.

## Цель

Заменить свободный цикл вызова инструментов в `AnalysisAgent` на ограниченный граф аналитики, в котором `Qwen/Qwen3.8-27B` генерирует план, SQL и черновик отчёта, а сервер управляет порядком шагов, разрешает сущности, проверяет SQL, выполняет только чтение и связывает каждый вывод с сохранённым `resultId`.

## Архитектурное решение

Microsoft Agent Framework Workflows используется как in-process runtime графа в существующем приложении .NET 10. Модель не получает право произвольно вызывать серверные функции. Каждый узел графа вызывает ровно одну типизированную операцию, а переходы задаются кодом.

Вызов Qwen остаётся в нашем HTTP-адаптере. Это сохраняет фактический контракт Ario `/v1/chat/completions`, заголовок Bearer, `chat_template_kwargs.enable_thinking=false`, ограничение токенов и контролируемый разбор JSON. `Microsoft.Agents.AI.OpenAI` на первом этапе не используется: совместимость Ario с расширениями OpenAI SDK не должна быть скрытой предпосылкой миграции.

Существующие рубежи доверия сохраняются:

- `SqlGuard` и `SqlScopePolicy` проверяют каждый сгенерированный запрос;
- `ReadOnlyExecutor` открывает read-only транзакцию, задаёт `statement_timeout` и лимиты результата;
- значения выбранных сотрудников привязываются серверными параметрами, а не литералами модели;
- `ResultStore` создаёт фактические `resultId`;
- `ReportValidator` принимает только существующие результаты, колонки и вычислимые факты;
- `ReportRenderer` подставляет числа только из проверенных фактов.

## Целевой граф

1. `prepare` проверяет запрос, создаёт `RunContext`, повторно валидирует переданные `employeeId`.
2. `plan` просит Qwen вернуть `AnalysisPlan`: метрика, период, маршрут данных и упоминания сотрудников.
3. `resolve` ищет сотрудников серверным `IEmployeeResolver`. Неоднозначность завершает запуск со статусом `needs_clarification`, не выполняя SQL.
4. `acquire` выбирает один из двух серверных маршрутов:
   - `dashboard_metric` для готовой метрики;
   - `generated_sql` для гибкой аналитики.
5. Для `generated_sql` Qwen получает только релевантный срез каталога, обязательные параметры периода и выбранных сотрудников. SQL проходит `ToolDispatcher` и все текущие политики. Допускается одна попытка исправления после структурированной ошибки.
6. `report` просит Qwen создать `ReportSpec` только по фактическим `resultId`, колонкам и строкам. После ошибки `ReportValidator` допускается одна попытка исправления.
7. `finish` возвращает существующий `AnalysisResponse` без изменения HTTP-контракта.

## Контракты модели

Модель отвечает одним JSON-объектом на каждый этап. В ответе запрещён свободный текст вокруг JSON.

```csharp
public enum AnalysisDataRoute
{
    DashboardMetric,
    GeneratedSql
}

public sealed record AnalysisPlan(
    string MetricId,
    PeriodSpec Period,
    AnalysisDataRoute Route,
    string? DashboardMetric,
    string[] EmployeeMentions,
    string[] RelationHints);

public sealed record SqlDraft(string Sql, string MetricId);

public sealed record ReportDraft(ReportSpec Report);
```

Сервер повторно проверяет эти DTO. JSON модели не становится SQL-командой, выбором сотрудника или отчётом без соответствующей серверной проверки.

## Ограничения выполнения

- Целевая модель: `Qwen/Qwen3.8-27B`.
- Температура: `0.2`.
- Thinking: выключен через `chat_template_kwargs.enable_thinking=false`.
- Общий бюджет запуска: 120 секунд.
- Вызовы модели: план, SQL, отчёт и не более одной коррекции SQL и одной коррекции отчёта.
- Только один SQL-запрос данных на первую поставку. Несколько независимых наборов данных остаются за пределами этой миграции.
- Результат: не более 200 строк, 60 колонок, 200 символов в ячейке, 1 МиБ на результат и 4 МиБ на запуск.
- HTTP-маршрут `/api/ai/analysis`, локальный периметр, DTO ответа и Canvas остаются совместимыми.

## Обработка состояний

- `completed`: есть хотя бы один сохранённый результат и отчёт прошёл проверку.
- `needs_clarification`: сервер нашёл несколько допустимых сотрудников.
- `no_data`: запрос выполнен, но не вернул строк.
- `incomplete`: данные получены, но отчёт не удалось проверить или исчерпан бюджет.
- `failed`: данных не получено из-за ошибки провайдера, плана, политики или инфраструктуры.

Ни один путь не преобразует `failed`, `incomplete` или `no_data` в правдоподобный ответ с числами.

## Совместимость и развёртывание

`AnalysisAgent` остаётся временным legacy runner. Выбор runner выполняется сервером через `Analytics.Engine` со значениями `legacy` и `workflow`. Первая поставка включает быстрый откат на `legacy`; после прохождения живого набора сценариев значением по умолчанию становится `workflow`.

Пакет `Microsoft.Agents.AI.Workflows` фиксируется на версии `1.21.0`, а NuGet lock-файл коммитится. До миграции бизнес-логики обязательно должны пройти обычная Release-сборка и self-contained publish `win-x64`.

GigaChat не входит в целевую архитектуру. Существующий провайдер не удаляется этой работой, но новые workflow-контракты и промпты проектируются только под Qwen.

## Наблюдаемость

Публичный `steps` остаётся кратким и не содержит скрытые рассуждения. Стабильные имена шагов: `prepare`, `plan`, `resolve_entities`, `dashboard_metric` или `execute_sql`, `draft_report`, `validate_report`. Для каждого шага сохраняются статус, время, `resultId` и безопасный код ошибки.

SQL остаётся видимым пользователю в существующем раскрываемом блоке. Токены, пароль БД, connection string и необрезанные ответы провайдера в HTTP и лог не попадают.

## Критерии приёмки

1. Вопрос «Сравни количество поручений у Ивана Иванова и Босова Александра за 12 месяцев» возвращает проверенный график и таблицу из одного реального `resultId` либо явное уточнение.
2. Неоднозначное ФИО не приводит к SQL до ответа пользователя.
3. Любая ссылка отчёта на отсутствующий `resultId` или колонку отклоняется.
4. SQL без обязательного периода или серверной привязки выбранного сотрудника не выполняется.
5. `INSERT`, `UPDATE`, `DELETE`, DDL, запрещённые функции и отношения вне каталога блокируются существующими политиками.
6. Пустой результат возвращает `no_data`; усечённый результат помечается предупреждением.
7. Offline suite, HTTP smoke, frontend tests, Release build и self-contained publish проходят.
8. На живом наборе контрольных вопросов workflow не хуже legacy по корректности и имеет не более одной SQL-коррекции в 90% успешных запусков.

## Вне объёма

- создание read-only роли PostgreSQL: это отдельная эксплуатационная задача;
- перенос UI или приложения на другую платформу;
- несколько параллельных SQL-исследований в одном вопросе;
- долговременная память диалогов;
- автоматическое обучение модели;
- промышленное включение WrenAI;
- удаление legacy SQL endpoint и GigaChat-кода.

## WrenAI

WrenAI проверяется отдельно и не блокирует миграцию workflow. Spike переносит три метрики в MDL и сравнивает SQL/результаты на фиксированном наборе вопросов. Подключение к production-коду разрешено только после измеримого улучшения семантической корректности без ослабления `SqlGuard`, read-only выполнения и evidence-контракта.
