# Дорожная карта ARMGov Dashboard

Дата: 2026-06-21. Статус прототипа: **рабочее демо** (остаётся демо — фокус карты на ценности,
не на продакшен-обвязке). Сопутствующие: `PROJECT-OVERVIEW.md`, `TECHNICAL.md`.

## Принцип приоритизации
Прототип показывает ценность процессной аналитики для ЛПР. Поэтому **H1 = быстрые «вау»-метрики
и удобство демонстрации**. Продуктивизация (безопасность, доступ через OData, кэш) — зафиксирована
как технический долг (H2/H3), но осознанно отложена, пока проект в статусе демо.

## Текущее состояние (готово)
Обзор для руководителя (пропускная способность, узкое место, застрявшие, «что горит», светофор),
страница процесса (цикл P50/P95, воронка, длительность маршрута, тренд, прогноз срыва, топы,
возвраты/«битва правок», качество решения, загрузка, просрочки, **приток/отток**, **с первого
раза**, **петли**, **разрезы**), ИИ-сводка/чат/«разбор по ⓘ», бэк-офис (подключения, профили,
пороги, промпты), перетаскиваемая раскладка + ширина (localStorage), период, печать, Docker/портабл.

## H1 — Быстрые ценности (сейчас, дни) — ПРИОРИТЕТ
Реализуемо на текущих данных, без новых источников и без прод-обвязки.

1. **Поток-эффективность: работа vs ожидание** ⭐ (рекомендуемый первый)
   - Что: разложить цикл на «работа» (открытие→решение) и «ожидание» (лежит в очереди); показать %.
   - Зачем ЛПР: «документ 9 из 10 дней просто ждёт» — ускорять надо передачу/распределение, не людей.
   - Данные: `created` / `MarkRead` / `completed` — есть. Эвристика, без новых таблиц.
   - Объём: новый блок на странице процесса (+ поле в `/api/process`). Малый.

2. **Время передачи между этапами (handover delay)**
   - Что: разрыв между завершением одного этапа и стартом следующего — потери «между столами».
   - Зачем: где процесс рвётся на стыках (не виноват ни один исполнитель).
   - Данные: `assignment.completed` → следующий `assignment.created`. Есть. Малый.

3. **ИИ-сводка по конкретному процессу**
   - Что: кнопка «сводка ИИ» на странице процесса (сейчас сводка только по региону).
   - Данные: переиспользуем `BuildAiSummary` с контекстом одного процесса. Малый. (Зависит от доступности LLM.)

4. **Сравнение периодов (дельты ↑↓)**
   - Что: к ключевым метрикам — изменение к прошлому периоду (стрелка/процент).
   - Зачем: «стало лучше или хуже» — динамика, а не снимок.
   - Данные: инфраструктура периода есть; считаем текущий vs предыдущий. Средний.

5. **Экспорт в CSV/Excel**
   - Что: выгрузка списков (просроченные, по подразделению, по исполнителю) и сводных метрик.
   - Зачем: руководителю — забрать в отчёт/совещание. Малый.

_Опционально в H1:_ перетаскивание блоков на стартовой; произвольный диапазон дат; проактивные
ИИ-алерты («X резко вырос»).

## H2 — Продуктивизация (недели, если из демо пойдём в пилот)
Технический долг для реального внедрения. Сейчас отложено.
- **Аутентификация пользователей + роли** (профили → реальные роли по логину; сейчас открыто на порту).
- **Доступ к данным через OData / Public API RX** вместо прямого чтения схемы БД — снимает главный
  риск хрупкости к именам таблиц и GUID-дискриминаторам.
- **Отдельная read-only сервисная учётка** (least privilege; сейчас admin).
- **Кэш/материализация агрегатов** (сейчас всё на лету; на больших объёмах будет медленно).
- **Внешний доступ** по HTTPS / обратный прокси; защита бэк-офиса.
- **Приватность LLM**: ФИО уходят на внешнюю модель → модель в контуре или обезличивание.

---

## H3 — Зрелость (стратегия)
- Прогностика (риск срыва по историческим маршрутам, прогноз остатка времени).
- Конформанс к эталонному маршруту (отклонения, пропуски, неожиданные переходы).
- Organizational mining: сеть передачи работы, «незаменимые» узлы.
- Концепт-дрифт (рост цикла во времени), аномалии/выбросы.
- ИИ в контуре + разбор текста резолюций (содержательная аналитика причин).
- Материализованная история (снимки-джобы), автотесты, CI, мониторинг/логирование.

---

## Главный технический долг (зафиксировать явно)
**Прямая привязка к физической схеме БД** (имена таблиц, GUID-дискриминаторы конкретного стенда):
для демо приемлемо, для прод — первый кандидат на переработку (→ OData/Public API, H2).
Прочее: нет аутентификации, admin-учётка, секреты в `config.json` на диске, «тема» обращений пуста.

## Рекомендуемый первый шаг
**H1 #1 «Поток-эффективность (работа vs ожидание)»** — сильнейший управленческий инсайт на уже
имеющихся данных, малый объём. Дальше — handover delay и сравнение периодов.
