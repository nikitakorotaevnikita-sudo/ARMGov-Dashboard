# Дизайн: смысловая группировка блоков процесса по секциям

Дата: 2026-06-25

## Проблема
Блоки на странице процесса — плоская сетка без логической группировки. Для демо и
восприятия нужно сгруппировать по смыслу с заголовками секций, сохранив кастомизацию.

## Решение
6 секций с заголовками, перетаскивание блоков — только внутри своей секции.

### Карта секций (блок → секция)
1. **Объём и поток**: funnel, backlog
2. **Скорость и качество**: stages, hist, pickup, flow, formal
3. **Дисциплина и риск**: trend, risk, overdue
4. **Переделки и возвраты**: rework, ftr, loops
5. **Люди**: workload, neg, pos
6. **Срезы**: breakdown

Все 17 блоков распределены.

### Механика
- `PSECTIONS` — статический массив `[{title, keys:[…]}]` рядом с `PCARDS`.
- `renderProcess` рисует по секциям: заголовок `.psection-h` + сетка блоков секции.
  KPI-строка сверху без изменений.
- Внутри секции порядок берётся из сохранённой раскладки (глобальный `order`,
  отфильтрованный по ключам секции). Формат раскладки не меняется → старые не ломаются.
- `pDrop` игнорирует перетаскивание между секциями (через `sectionOf(key)`).
  Ширина (`pToggleWide`) и «сбросить раскладку» — без изменений.
- Секция, где все блоки скрыты профилем роли (`prHas`), не отображается (нет пустых заголовков).

### Вид
KPI-строка, затем секции: заголовок секции (капс, акцентная подчёркивающая линия) и под ним сетка карточек.

## Не входит
- Изменение состава метрик/бэкенда.
- Изменение профилей ролей и формата сохранённой раскладки.

## Риск
Низкий: правки только в `renderProcess` и `pDrop` (+ CSS заголовка) в index.html.
