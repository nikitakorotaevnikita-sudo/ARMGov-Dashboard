# Страница «Аналитика по запросу» — дизайн

**Дата:** 2026-09-16
**Проект:** ARMGov-Dashboard (прототип проверки гипотез)
**Автор постановки:** Никита Коротаев
**Основание:** ИИ-харнесс, реализованный в ветке `ai-sql-harness` и слитый в master (`Program.cs`, регион «ИИ-харнесс»)

## 1. Задача

Руководитель задаёт вопрос об аналитике в свободной форме, а страница сама показывает **картинку**, а не текст: график, построенный по фактическому результату ИИ-харнесса, с возможностью переключить вид представления.

Проверяемая гипотеза: руководитель получает ответ в том виде, в котором привык принимать решения — визуально, — не формулируя заранее, каким графиком это показать, и не обращаясь к аналитику.

Отличие от существующего чата: там ответ текстовый, а данные, добытые харнессом, выбрасываются — в протокол шагов попадают лишь пять строк превью. Здесь данные становятся главным результатом.

## 2. Решения по объёму (согласованы)

| Развилка | Решение |
|---|---|
| Роль страницы | Визуализация главная, чат — способ её заказать |
| Кто выбирает вид | Код по форме данных; модель подсказывает предпочтительный из возможных |
| Источник данных для графика | Только фактический результат; модель указывает на массив, но не переписывает значения |
| Набор представлений | Пять табличных видов: столбики, динамика, доли, плитки KPI, таблица |
| Границы | Смотреть и переключать вид; история в пределах сессии; выгрузки и закрепления нет |
| Архитектура | Харнесс отдаёт датасет, клиент выбирает вид и рисует |

Схемы связей (маршрут процесса, дерево подразделений) — **вне объёма**: это другой класс данных, связи вместо агрегатов, и он требует своего формата результата и движка раскладки.

## 3. Ограничения

- .NET 10 + `HttpListener`, Npgsql; серверная логика в `Program.cs`, фронтенд в `index.html` и `style.css` — архитектуру прототипа не меняем.
- **Только `SELECT`** — нерушимое правило; страница не добавляет новых путей к данным, она использует существующий харнесс.
- **Метрики должны сходиться** — цифра на графике обязана совпадать с цифрой в тексте ответа и на дашборде. Это обеспечивается тем, что источник один: фактический результат прогона.
- Графики рисуются своими SVG-примитивами, без внешних библиотек: интернета в контуре заказчика нет, а прототип уже умеет `svgBars`, `svgSpark`, `svgStack`, треемап.
- Палитра — только токены из `tokens.css`, общие с `presale-dashboard`.
- Язык интерфейса и кода — русский.

## 5. Контракт: поле `dataset`

Добавляется в ответ `POST /api/ai/sql` рядом с `reply`, `steps`, `elapsedMs`, `truncated`. Поле необязательное: дровер чата его игнорирует, старое поведение не меняется.

```json
"dataset": {
  "source": "sql",
  "cols": [
    {"name": "unit",    "title": "НОР",        "type": "text"},
    {"name": "overdue", "title": "Просрочено", "type": "number"}
  ],
  "rows": [["ДИТ", 412], ["ДФ", 311], ["Минобр", 208]],
  "rowCount": 12,
  "truncated": false,
  "hint": "bars"
}
```

| Поле | Смысл |
|---|---|
| `source` | Происхождение: `sql`, `tool:<имя>`, `preload:overview`. Показывается пользователю подписью под холстом |
| `cols[].type` | `text` \| `number` \| `date` \| `bool`. Ставит **сервер**, не модель |
| `rows` | Значения как есть, без округлений и переписывания |
| `rowCount` | Сколько строк всего (может быть больше, чем в `rows`) |
| `truncated` | Выдача усечена лимитом исполнителя |
| `hint` | Предпочтительный вид по мнению модели; необязателен |

Рядом, не внутри `dataset`, а в шаге протокола с `action:"answer"` (в массиве `steps`), сервер
может положить поле `datasetError` (строка) — причину, по которой `chart` был указан моделью, но
датасет не собрался (не тот массив, `tool:` не совпал с реально вызванным инструментом, ошибка
при сборке). `dataset` в этом случае отсутствует. `index.html` читает `datasetError` из
последнего шага `answer` и показывает его текстом рядом с подписью «для этого вопроса графика
нет», отличая тем самым «график не нужен» от «график не собрался».

**Типы колонок ставит сервер.** Для SQL-результата — из `NpgsqlDataReader.GetFieldType`: база сама знает, где текст, где число, где дата. Для массива из ответа инструмента — выводом по значениям. Типы определяют набор допустимых видов, поэтому гадать здесь нельзя.

**`hint` — подсказка, а не приказ.** Он сужает выбор внутри возможного, но не расширяет его: если модель предложила `line`, а колонки-даты в данных нет, подсказка отбрасывается.

## 6. Как сервер собирает датасет

Модель в действии `answer` может дополнительно указать, что визуализировать:

```json
{"thought": "…", "action": "answer", "text": "…",
 "chart": {"from": "tool:leaders", "array": "items",
           "columns": ["name", "overdue"], "view": "bars"}}
```

Модель называет **массив и колонки**; значения подставляет код из фактического результата.
Переписать числа она не может — их нет в её ответе. Это прямое следствие решения «источник
данных — только фактический результат».

Системный промпт агента дополняется описанием поля `chart`: когда его заполнять, какие имена
массивов доступны у каждого инструмента и что `view` — лишь пожелание. Поле необязательное:
ответ без него остаётся валидным, и старое поведение чата не меняется.

Три случая, по убыванию частоты:

1. **Ответ из инструмента.** `chart.from = "tool:<имя>"`, `chart.array` — имя массива в JSON инструмента (`items`, `processes`). Код берёт массив, оставляет перечисленные колонки, выводит типы.
2. **Ответ из SQL.** Берётся последний **успешный** `sql`-шаг: у него уже есть `cols` и строки. Неудачные попытки самокоррекции пропускаются. Указание модели не требуется, но `chart.view` учитывается как подсказка.
3. **Ответ из предзагрузки, без шагов.** Самый частый случай на демо («сколько просрочено»). Модель указывает `{"from":"preload:overview","array":"processes","columns":["name","overdue"]}`.

Если модель ничего не указала и `sql`-шагов не было — `dataset` отсутствует. Это штатное состояние, а не ошибка: страница показывает текст ответа и подпись «для этого вопроса графика нет».

**Ограничения датасета:** не более 12 колонок и не более 200 строк — общий потолок исполнителя `SqlRun` (`SqlMaxRows`). Для SQL-датасета конкретно этой страницы фактический потолок ниже: цикл агента вызывает `SqlRun(eff, 50)` с явным лимитом 50 строк, поэтому SQL-шаг в «Аналитике по запросу» обрезается на 50, а не на 200. Подпись усечения на экране честная (называет реально показанное число), расходится только этот текст с фактическим лимитом. Вид «таблица» показывает все колонки датасета, а не все колонки исходного результата: если в запросе их было больше двенадцати, лишние в датасет не попадают и нигде не показываются. Для прототипа это приемлемо; если упрёмся — поднимем потолок.

## 7. Клиент: выбор вида

`pickViews(dataset)` — чистая функция от формы данных, без обращения к смыслу:

| Форма данных | Допустимые виды | По умолчанию |
|---|---|---|
| 1 строка, только числа | плитки KPI, таблица | плитки |
| текст + 1 число | столбики, доли, таблица | столбики |
| дата/период + 1–3 числа | динамика, столбики, таблица | динамика |
| текст + 2 и более чисел | столбики несколькими сериями, таблица | столбики |
| 2 текстовых + число | таблица | таблица |
| чисел нет (только текст, даты, логические) | таблица | таблица |

`hint` выбирает внутри допустимого набора; недопустимый `hint` игнорируется.

**Правила отображения:**

- **Сортировка:** столбики — по убыванию значения (руководителя интересует «у кого хуже»); динамика — по времени.
- **Много категорий:** больше 20 столбиков не рисуется — показываются топ-20 и подпись «показаны 20 из 128, остальные в таблице». Молчаливое обрезание запрещено: иначе руководитель решит, что подразделений двадцать.
- **Доли:** при 6 и менее категориях — кольцо с легендой, иначе горизонтальные полосы с процентами. Вид не предлагается, если есть отрицательные значения.
- **Переключатель:** ряд чипов над холстом; недопустимые виды не показываются вовсе, а не блокируются.

**Реализация видов:**

| Вид | Как делается |
|---|---|
| Столбики | существующий `svgBars` + подписи значений и сортировка; для нескольких показателей — серии рядом (не стопкой: стопка уместна для частей целого, а два произвольных показателя частями целого не являются) |
| Динамика | на базе `svgSpark`, полноразмерная: ось времени, подписи, точки |
| Доли | новый: кольцо либо горизонтальные полосы с процентами |
| Плитки KPI | существующая разметка `.kpi` со стартового экрана |
| Таблица | существующий табличный стиль с `tabular-nums` |

**Размещение кода.** Рисовалка выносится в новый `charts.js`, подключаемый рядом с `style.css`; `svgBars`, `svgSpark`, `svgStack` переезжают туда же, вызовы на существующих экранах не меняются. Причина: `index.html` уже около 240 КБ, и пять новых видов сделают его нечитаемым.

## 8. Экран

Шестой пункт сайдбара — «Аналитика по запросу».

```
┌ шапка ───────────────────────────────────────────────────────┐
│ сайдбар │ Аналитика по запросу                                │
│         │ [ спросите про данные…                        ▶ ]   │
│         │ быстрые вопросы:  чип · чип · чип                   │
│         │ ┌ холст ───────────── Столбики · Доли · Таблица ──┐ │
│         │ │ Просрочка по подразделениям                     │ │
│         │ │             [ Г Р А Ф И К ]                     │ │
│         │ │ данные: инструмент leaders · 12 строк           │ │
│         │ └─────────────────────────────────────────────────┘ │
│         │ Хуже всех ДИТ — 412 просроченных из 1580.           │
│         │ ▸ Размышления · 2 шага · 9,7 с                      │
│         │ История:  просрочка по НОР · динамика за год · …    │
└─────────┴─────────────────────────────────────────────────────┘
```

- Текстовый ответ — одна-две строки под холстом, а не лента диалога.
- Блок «Размышления» переиспользуется из дровера чата: он уже показывает шаги, аргументы вызова инструмента и текст SQL.
- История — строка чипов внизу; клик восстанавливает график, ответ и протокол. Живёт в памяти вкладки, на сервер ничего не уходит.
- Быстрые вопросы берутся из существующего списка `chatPrompts` в конфигурации.

Страница всегда обращается к `/api/ai/sql` (режим глубокого анализа), тумблера здесь нет: без данных визуализировать нечего. Следствие: страница работает только при локальном вызове — таково ограничение эндпоинтов харнесса.

## 9. Вырожденные случаи

| Что случилось | Что видит руководитель |
|---|---|
| Модель недоступна | плашка с текстом ошибки; поле ввода остаётся рабочим |
| Ответ без датасета | текст и «Размышления»; под холстом «для этого вопроса графика нет» |
| Запрос вернул 0 строк | «данных по такому условию нет»; запрос виден в «Размышлениях» |
| Одно число | плитка KPI — нормальный вид, а не отсутствие графика |
| Срезано 200 строк | подпись «показаны первые 200 строк» рядом с источником |
| Ожидание ответа | спиннер с бегущим временем и текстом «собираю данные» |

Последнее не косметика: цикл идёт до 60 секунд, и пятнадцать секунд неподвижного экрана на демо читаются как поломка.

## 10. Тестирование

**Правила выбора вида** — `tests/charts.test.js`, запуск `node tests/charts.test.js` (Node 24 на машине есть). Проверяются все шесть строк таблицы из раздела 7 плюс: отрицательные значения исключают «доли», недопустимый `hint` игнорируется, допустимый `hint` меняет вид по умолчанию. Это чистая функция, и именно она тихо ломается при любой правке — поэтому тест обязателен.

**Контракт датасета** — в существующий `tests/smoke.py`: вопрос, закрывающийся инструментом, возвращает `dataset` с проставленными типами колонок; вопрос без визуализируемых данных возвращает ответ без `dataset` и это не ошибка; `rows` не пустой при `rowCount > 0`; `source` соответствует фактически использованному шагу.

**Живая проверка в браузере** — три вопроса разной формы: «просрочка по подразделениям» (столбики), «динамика за год» (динамика), «сколько просрочено» (плитки KPI). Смотрим, что переключатель предлагает разумный набор и что подпись источника совпадает с протоколом шагов.

## 11. Вне объёма (YAGNI)

- Схемы связей: маршрут процесса, дерево подразделений.
- Выгрузка картинки и данных, закрепление графика на дашборде — это шаг в сторону припаркованного генератора отчётов.
- Сохранение истории на сервере между сессиями.
- Проваливание из графика в список задач по клику на столбик.
- Сравнение двух вопросов рядом на одном холсте.
