# Дизайн: серверный кэш + кнопка «Обновить данные»

Дата: 2026-06-24

## Проблема

После роста БД (assignment 355к, task 81к, workflowhistory 729к) страницы дашборда стали
медленными: каждый эндпоинт выпускает ~28 отдельных агрегаций, каждая заново сканирует один
и тот же срез join'а assignment×task. Повторные открытия/навигация пересчитывают всё с нуля.

## Решение (вариант A — мемоизация на уровне диспетчера)

Аналитические данные не realtime — их можно кэшировать на короткий TTL. Кнопка «Обновить данные»
даёт пользователю явный сброс кэша, когда нужны свежие цифры.

### 1. Серверный кэш
- `static readonly ConcurrentDictionary<string,(DateTime at, string json)> Cache`.
- Ключ = `path + "?" + rawQuery` (полный URL запроса).
- TTL = 60 секунд. Если запись свежая — отдаём готовый JSON из памяти, в БД не ходим.
- Кэшируемые пути: `/api/processes`, `/api/overview`, `/api/process`, `/api/process/stuck`,
  `/api/process/workload`, `/api/process/departments`, `/api/process/by-kind`,
  `/api/process/dept-tasks`.
- НЕ кэшируем: `/api/task`, `/api/performer` (точечные дриллдауны), `/api/export`,
  `/api/config*`, `/api/ai/*` (своя логика/`?force=1`).
- Билдеры (`Build*`) не меняются — кэш только оборачивает их вызовы. Числа на экране те же.

### 2. Эндпоинт сброса
- `POST /api/refresh` → `Cache.Clear()` → `{ ok:true }`.
- Аналог существующего паттерна `?force=1` у `/api/ai/summary`.

### 3. Фронтенд — кнопка
- Кнопка «↻ Обновить данные» в шапке (`.app-header`) рядом с `#meta`.
- Клик: дизейбл+индикатор → `POST /api/refresh` → перерисовка текущего экрана
  (`load()` для обзора / повторный `fetch` для процесса) → `#meta` = «обновлено сейчас».
- `#meta` показывает время данных (поле `cachedAt` в ответе, либо `generatedAt`).
- Существующий `setInterval(load,60000)` остаётся: при живом кэше почти бесплатен.

### Обработка ошибок
- Ошибка `POST /api/refresh` → кнопку вернуть в норму, показать «не удалось обновить» в `#meta`.
- `ConcurrentDictionary` — потокобезопасно.

## Что НЕ входит (отдельные шаги)
- Дедупликация подзапроса MarkRead (workflowhistory) внутри одной сборки страницы.
- Триграммный индекс под `subject` для НПА, фикс возвратов, замена `status::text=`.

## Риски
Минимальные: билдеры не трогаем, кэш — добавочный слой. Возможный нюанс — пользователь
видит данные «возрастом до 60 с»; кнопка и TTL это закрывают.
